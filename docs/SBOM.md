# Software Bill of Materials (SBOM)

Every release artifact — compiled binaries and the container image — is
accompanied by a CycloneDX JSON SBOM generated by
[syft](https://github.com/anchore/syft) and signed with
[cosign](https://github.com/sigstore/cosign) using keyless Sigstore signing.

## What is included

- **Binaries**: each platform binary (`soroauth-linux-amd64`, `soroauth-darwin-arm64`,
  etc.) gets its own SBOM file. Each file lists all Go module dependencies at
  their exact committed versions, as reported by the binary's embedded module
  metadata.
- **Container image**: the image pushed to `ghcr.io/soroauth/soroauth-go` is
  signed with cosign after every release push.

## Verification — binaries

Download the binary, its SBOM (`.sbom.json`), and its bundle (`.sbom.json.bundle`)
from the GitHub release page. Install `cosign` (version 2.x), then run:

```sh
cosign verify-blob \
  --bundle soroauth-linux-amd64.sbom.json.bundle \
  --certificate-identity "https://github.com/soroauth/soroauth-go/.github/workflows/release.yml@refs/tags/v0.1.0" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  soroauth-linux-amd64.sbom.json
```

Substitute the correct tag for `v0.1.0`. A successful verification prints:
```
Verified OK
```

The bundle contains the short-lived Fulcio certificate and the Rekor
transparency log entry. No long-lived signing key is stored anywhere.

## Verification — container image

```sh
cosign verify \
  --certificate-identity "https://github.com/soroauth/soroauth-go/.github/workflows/release.yml@refs/tags/v0.1.0" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  ghcr.io/soroauth/soroauth-go:v0.1.0
```

## SBOM format

SBOMs use [CycloneDX](https://cyclonedx.org/) JSON format (version 1.6).
They are generated by syft from the compiled binary using the binary's embedded
`go.mod` module list, so dependencies are recorded at the exact versions that
were compiled in, not at the versions currently in the working tree.

## Signing details

Signing uses Sigstore [keyless signing](https://docs.sigstore.dev/signing/overview/):

1. The release workflow requests a short-lived OIDC token from GitHub Actions.
2. That token is exchanged with Sigstore's Fulcio CA for a certificate binding
   the workflow's identity (`github.com/soroauth/soroauth-go/.github/workflows/release.yml`)
   to an ephemeral key pair.
3. The SBOM (or image digest) is signed with the ephemeral key.
4. The signature and certificate are recorded in the Rekor append-only
   transparency log.
5. The bundle file packages the certificate and Rekor entry for offline
   verification.

No private signing key is stored in this repository or in any secret. The
Rekor log entry is public and can be inspected independently.
